# ROB completion timing iteration

Date: 2026-07-25

## Objective

Remove the complete-SoC critical path from the load/store queue through execution completion
selection to the clock-enable pin of the ROB completion payload registers. Preserve issue,
wakeup, completion, and commit latency while targeting a 100 MHz CPU clock.

## Path diagnosis

The committed hierarchical-TLB baseline completed full-SoC implementation with WNS
`-0.810774 ns` and TNS `-367.200470 ns`. Its worst path ran from
`loadStoreQueue/loads_7_virtualAddress_reg[16]/C` to
`rob/stagedResult_3_reg[29]/CE`: 10.222 ns data delay, 2.522 ns logic, 7.700 ns route, and 13
logic levels. Routing contributed 75.3% of the delay, but the path also combined LSQ readiness,
execution-lane arbitration, completion validity, and a wide payload-register enable. The
negative slack therefore cannot be attributed to placement alone.

## Design

`stagedCompletionHits` remains the only validity state for the registered ROB completion
boundary. Each completion lane now captures its payload every non-flush cycle instead of using
the combinational `completionValid` signal as the enable for every payload field. Invalid payload
samples are never consumed because entry updates and physical-register wakeup remain gated by
the registered hit bitmap.

This keeps completion visibility and wakeup latency unchanged while preventing LSQ address and
execution selection logic from reaching the payload-register CE pins. The change is entirely in
Scala/SpinalHDL; `rtl/mycpu_top.v` is regenerated by the locked publisher. A stale exact lint
scope count from the preceding TLB iteration was also corrected from 14 to the generated
inventory of six ordinary `UNUSEDSIGNAL` blocks plus one DiffTest-special block.

## Registered LSU issue boundary

The LSU issue-address boundary now has a two-entry FIFO in front of the existing
operand register. Its enqueue-ready signal is registered from the FIFO's next
occupancy, so current-cycle `aguReady` can no longer drive issue selection or
queue compaction. The three total slots absorb the registered-ready round trip
and retain one LSU issue per cycle in steady state. Other execution ports keep
their original lower-cost address/operand pipeline.

The first implementation accidentally allocated a second complete pair of LSU
uop slots while leaving the old port-indexed slot unused. Unwaived Verilator
lint exposed 61 new `UNUSEDSIGNAL` warnings. The final implementation reuses the
existing LSU address register as FIFO slot zero and adds only one packed overflow
slot. Unwaived lint consequently returns to the exact prior set: 739 warnings,
only `UNUSEDSIGNAL` and `CMPCONST`, signature
`cc8a7027d06955889bf5e4f8df5b3881cc45be057f23610efe62c00d59bc9af3`.

## Flush-independent IQ wakeup and ordered skid storage

ROB now exposes a raw registered-completion candidate bitmap for IQ wakeup. The
architectural wakeup output remains suppressed during flush for PRF and rename
state, while each IQ may use the raw candidate because flush has priority over
all IQ sequential updates. A directed ROB test locks this distinction: raw IQ
wakeup remains visible during the flush combinational phase, architectural
wakeup is zero, and both ROB/IQ state are cleared on the edge.

The LSU address FIFO is also implemented as ordered front/overflow skid storage
instead of two slots selected by read and write pointers. The front slot feeds
the PRF directly; the overflow slot shifts forward only when the front dequeues.
This removes the wide write-pointer mux while preserving the same two-entry
capacity, registered enqueue-ready boundary, and three total in-flight slots.

## Registered completion identity

The next candidate registers only each completion lane's valid bit, ROB pointer,
and payload at the ROB boundary. On the following cycle, the registered pointer
selects its ROB index and validates the generation bit locally against that
entry. Entry completion and raw IQ wakeup consume this local match. The old
design also registered a hit bitmap on arrival and consumed it on the following
cycle, so this transformation retains the same completion-to-wakeup latency
while cutting the LSQ-to-32-way-pointer-comparison path.

## Ring-window completion validation

The wakeup path now determines whether a registered completion tag is live with
the ring invariant `(completionPointer - commitPointer) mod 64 < occupancy`.
This six-bit subtract/compare rejects tags before the head, beyond the tail, and
from a flushed generation without reading all 32 ROB entries. ROB payload writes
retain the stricter index, generation, valid, and incomplete checks locally.

This follows the `la32r-linux` ysyx design's important boundary: writeback tags
are broadcast directly to rename, PRF, and IQ consumers, while ROB data is
addressed by `robPtr.index`; ROB completion state is not fed back into wakeup
qualification. The local design keeps an additional live-window check to retain
the existing stale-completion safety contract.

## Decoupled IQ payload-ready updates

IQ slot-valid state and payload-ready state now use independent update trees.
Issue selection clears only the narrow `slotValid` bit; it no longer suppresses
wakeup writes to an invalidated payload. This removes `issueSlot` from the D
cone of every payload source-ready register while retaining enqueue priority,
wakeup capture, age order, and one-issue-per-port throughput.

## Recovery-epoch completion validation

The next candidate assigns every renamed uop an eight-bit recovery epoch and
propagates it through execution and the LSQ completion sidecars. A flush
increments the epoch. Registered completions may wake the PRF and IQ only when
their epoch equals the current epoch; strict ROB payload writes additionally
retain pointer, entry-valid, incomplete, and entry-epoch checks. This replaces
the live-window subtract/compare and its commit-pointer/occupancy inputs with a
local equality check while continuing to reject delayed pre-flush completions.

## Stationary two-slot LSU address FIFO

The recovery epoch remains in place, while the LSU address buffer now uses two
stationary payload registers selected by one-bit read and write pointers. An
enqueue writes exactly one selected slot and advances the write pointer; a
dequeue advances only the read pointer. It no longer promotes the complete
overflow uop into the front register, so `aguReady` cannot directly toggle a
wide address-uop register enable.
