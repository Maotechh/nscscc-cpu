# Wide backend wakeup, decoupled Store data, and critical Load refill

Date: 2026-07-26

## Scope

This iteration combines the queued timing/performance work after commit `d126f57`:

- synchronous ROB commit-payload banks with narrow retirement hot state;
- commit-side predictor payload predecode;
- direct ALU wakeup and fixed-latency MUL tag wakeup/data forwarding;
- an 8-entry Store-data queue decoupled from Store address issue;
- L1D response on target refill-beat availability;
- data-side critical-beat propagation and AXI wrapping refill.

All implementation changes are in Scala/SpinalHDL. `rtl/mycpu_top.v` is regenerated by
`make generate-core`; no handwritten Verilog was added.

## Correctness fixes found by directed testing

Store dispatch must be atomic across the LSU address IQ and Store-data queue. Peer-ready valid
gating prevents either half from accepting the same Store repeatedly under backpressure. The LSU
operand register also separates current-operand consumption from next-uop refill, so a Store-data
PRF conflict cannot replay an AGU request already accepted. Finally, byte Store formatting uses
explicit lane placement; a dynamic shift previously produced zero for a nonzero byte lane.

The LSQ records Store address and data independently, blocks overlapping younger Loads until an
older Store's data is available, and reports normal Store completion only after both halves arrive.
Exception and failed-SC completion remain precise.

## Critical-beat A/B result

All runs used Chiplab `func/func_lab19`, NEMU DiffTest, bus-delay seed `5570815`, a freshly rebuilt
Verilator model, syscall termination, and the locked end PC.

| Variant | Result |
| --- | ---: |
| L1D early response, critical beat forced to 0 on I and D | 533,744 cycles |
| I-side critical-first only | 536,336 cycles |
| I- and D-side critical-first | 536,336 cycles |
| D-side critical-first only | 533,744 cycles |

I-side critical-first is rejected because it regresses this workload by 2,592 cycles (0.486%).
The final candidate fixes I-side refill at beat 0 and retains D-side critical-first. D-side
critical-first is neutral in `func_lab19`; its value must be decided by real `perf20` memory-heavy
programs, not by expanding the local result into a hardware performance claim.
